# Evolução integrada — 26/11/2026

## Estrutura preservada

A API mantém Java 17/Spring Boot, controllers, services, repositories JPA, entidades e DTOs. O mobile mantém Expo 57/React Native, Expo Router, AuthContext/AccountContext, serviços HTTP e traduções. Existem apenas dois valores válidos para `X-API-Version`: `1` e `2`; os documentos JSON e as páginas visuais são representações desses mesmos contratos.

## Criação de quizzes e admin local

A revisão anterior retirou o CRUD do Swagger público e bloqueou a escrita para `USER`. Não foi um campo novo obrigatório: título, descrição, dificuldade e categoria continuam sendo os campos obrigatórios. Agora o Swagger V2 volta a documentar a autoria, identificada como ADMIN; o servidor continua devolvendo 403 para jogadores.

O bootstrap só funciona com perfil `local`/`dev`, `DEV_ADMIN_ENABLED=true` e `DEV_ADMIN_PASSWORD` definido. Se `prod` estiver entre os perfis ativos, o bootstrap não é registrado. A conta é criada apenas quando `isaac@gmail.com` ainda não existe; nunca altera senha ou papel de uma conta existente. Por padrão, esses perfis usam bancos separados (`data/animequiz-local` e `data/animequiz-dev`), preservando o banco padrão anterior; `DB_URL` pode alterar essa escolha.

No PowerShell, na pasta da API:

```powershell
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:DEV_ADMIN_ENABLED = 'true'
$env:DEV_ADMIN_PASSWORD = '123123123'
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Run-Api.ps1
```

Para entrar, use `POST /auth/login` com `{"email":"isaac@gmail.com","password":"123123123"}`. Copie somente `accessToken` em Authorize. A senha é um exemplo público e fraco, exclusivo da demonstração local: somente o hash BCrypt é gravado no banco. Para produção, use perfil `prod`, mantenha esse bootstrap desativado e provisione um administrador com senha forte por um procedimento controlado. Reiniciar o servidor não promove uma conta USER de mesmo e-mail.

Para o servidor publicado, há um procedimento independente, desativado por padrão, com senha privada forte e autorização explícita para atualizar uma conta existente: [Administrador no Render](ADMIN_RENDER.md). Ele não habilita o inicializador de demonstração no perfil prod.

## Criar conteúdo e conferir no mobile

```http
POST /quizzes
Authorization: Bearer <token-do-admin>
X-API-Version: 2
Content-Type: application/json

{
  "title": "Meu quiz de anime",
  "description": "Um desafio criado pelo administrador.",
  "difficulty": "DIFICIL",
  "category": "SHONEN",
  "imageUrl": "https://seu-servidor.example/capas/anime.png",
  "imageAltText": "Ilustração do anime escolhido",
  "englishTitle": "My anime quiz",
  "englishDescription": "A challenge created by the administrator."
}
```

Depois crie perguntas em `POST /questions` (`quizId`, `text`, `englishText` opcional) e quatro alternativas em `POST /options` (`questionId`, `text`, `isCorrect`, `englishText` opcional), com uma correta por pergunta. O gabarito é entrada administrativa, nunca saída do jogador. Para editar, use os respectivos PUTs; DELETE continua respeitando as referências existentes e retorna 409 quando a exclusão causaria inconsistências.

O mobile precisa apontar para **a mesma instância da API** em que o admin criou o conteúdo. O admin criado no H2 local não existe automaticamente no Render. Para testar com Expo Go/emulador, configure `EXPO_PUBLIC_API_URL` antes de iniciar Metro; no emulador Android, `http://10.0.2.2:8080` aponta para o computador. No celular físico, use o IP da rede local e permita a porta no firewall. Um APK distribuído deve usar a API pública HTTPS; variáveis `EXPO_PUBLIC_*` são incorporadas ao bundle e nunca devem conter segredos.

## Idiomas e contratos

- `GET /quizzes?lang=pt-BR|en` e `GET /quizzes/{id}/questions?lang=pt-BR|en` no contrato 2.
- O catálogo inicial possui 8 quizzes, 16 perguntas por quiz, 128 perguntas e 512 alternativas em cada idioma.
- IDs de quizzes, perguntas e alternativas são os mesmos entre idiomas; tentativas continuam enviando apenas IDs.
- Traduções são persistidas nos campos ingleses das entidades; o seeder completa somente os campos ausentes e preserva edições.
- Uma pergunta personalizada sem tradução completa do enunciado e das alternativas volta integralmente a português, com `contentLanguage: "pt-BR"`. Não mistura alternativas em idiomas diferentes.
- Valores de `lang` desconhecidos retornam 400. A V1 mantém seus DTOs básicos e conteúdo original em português.
- O app fixa o contrato 2 internamente, sem seletor de versão para o jogador. Trocar o idioma recarrega catálogo e perguntas; o idioma é capturado no início da leitura para não misturar páginas de idiomas diferentes.

## Capas e aparência

Capas de quiz ficam em `Quiz.imageUrl`/`imageAltText`; uploads de foto de perfil são um recurso separado. O admin pode fornecer uma URL HTTPS de imagem com direito de uso. A API não baixa essa URL no servidor. O catálogo inicial usa PNGs geométricos originais de 640×360 em `/media/quizzes/`; não foram copiadas artes de personagens nem logotipos de terceiros. A capa padrão é usada quando um novo quiz não recebe uma imagem.

No mobile, as capas aparecem na listagem e na abertura do quiz. Caminhos relativos das capas são resolvidos contra a origem configurada da API. Falhas de imagem exibem um fallback textual e não impedem jogar.

Foram mantidos temas escuros para preservar o contraste das telas existentes: Midnight, Eclipse, Oceano e Floresta. Os destaques são violeta, ciano, rosa, âmbar, menta e coral. A preferência pessoal é persistida por conta. Os arquivos de apresentação/CSS do Swagger não foram modificados.

## Perfil e foto

O cadastro gerava um identificador interno aleatório que acabava sendo exibido como nome. A apresentação agora dá prioridade a nome personalizado e nome cadastrado; identificadores automáticos não são tratados como nomes. Na ausência de nome, extrai o primeiro trecho do e-mail e coloca sua inicial em maiúscula.

O upload nativo usa `File` do Expo no multipart, compatível com o encoder do SDK 57, após recorte e conversão para JPEG. A API valida os bytes reais, dimensões e limite de 2 MiB. A leitura da foto exige JWT; o token vai no cabeçalho, não na URL. O componente considera conta, versão da foto e sessão ao refazer a imagem, permite tentar novamente após falha e volta ao avatar padrão quando a foto é removida. Falhas de favoritos não bloqueiam o carregamento do perfil/foto.

## Dificuldade, pontuação e limites

| Dificuldade | Máximo por pergunta no app | Pontos por acerto |
|---|---|---|
| FACIL | 30 s | 10 |
| MEDIO | 20 s | 20 |
| DIFICIL | 12 s | 30 |

O tempo retornado é o menor entre o limite configurado da pergunta e o limite da dificuldade. Ao esgotar, a pergunta fica sem resposta; não há pontos negativos. O relógio usa um prazo absoluto e se atualiza ao voltar do segundo plano. Trocar idioma não concede um prazo novo para a mesma pergunta.

O servidor continua calculando os acertos e pontos. O cronômetro é uma regra de interface, **não uma proteção antifraude contra um cliente alterado**. Não há bônus de velocidade. XP continua sendo a soma do melhor resultado de cada quiz; scores históricos não são reescritos. Uma rodada sem nenhuma resposta não gera tentativa, conforme a validação existente da API.

## Validação e entrega

Os resultados finais ficam no relatório de entrega. Os testes cobrem isolamento de contratos, permissões de administração, seed idempotente, BCrypt, produção com bootstrap bloqueado, tradução e IDs estáveis, capas, contagem/pontuação do catálogo, multipart real, idioma no cliente e contraste. Testes de integração local não substituem validação em celulares reais e no deploy de produção.
